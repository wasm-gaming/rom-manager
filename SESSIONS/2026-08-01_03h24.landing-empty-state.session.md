# 2026-08-01 03:24 - Landing Empty State: Brand Logo and Project Presentation

## Summary

Today the first thing anyone sees when the app opens with no folder ever picked
is two lines: `No folders opened` and an `Open Folder` button. Nothing says what
the tool is, what it does to a collection, or that nothing leaves the machine.

Turn that screen into a proper landing: an app logo, one sentence of what the
project is for, what it does (four capabilities), how it is used (three steps),
and the guarantee that everything runs in the browser against a local folder.
The `Open Folder` call to action stays the centre of it.

Scope is the **first** empty state only (`originsMap.size === 0`). The second
one — a remembered folder waiting to be re-authorised — keeps its current shape.

## Planned Changes — Part A: internationalisation

1. **`src/messages/en.yaml`, `src/messages/es.yaml` (NEW)**
   - One file per locale, nested by area (`welcome.*`, `header.*`, `prefs.*`,
     `tree.*`, `details.*`, `drop.*`, `intake.*`, `organize.*`, `errors.*`).
     English is the reference file: it holds every key, and a key missing from
     another locale falls back to it rather than showing a blank.
   - Placeholders are named — `Identificando {file}: {percent}%` — so a
     translation can move them around.
   - `src/messages/` sits inside the Vite root, so `import es from
     '../messages/es.yaml'` resolves in dev, build and vitest alike. Loading them
     needs **`@rollup/plugin-yaml`** as a devDependency and one line in
     `vite.config.ts`; the library build (`tsup`) only bundles `services/index.ts`
     and never sees them, so it is untouched. Types come from a small
     `src/types/yaml.d.ts` declaring `*.yaml` as a message record.

2. **`src/core/i18n.ts` (NEW, pure) + `src/core/i18n.test.ts`**
   - `LOCALES = ['es', 'en']`, `LocalePreference = Locale | 'auto'`,
     `DEFAULT_LOCALE = 'en'`.
   - `negotiateLocale(languages)` — picks from `navigator.languages`, matching
     `es-419`/`es-ES` to `es` by primary subtag, falling back to the default.
   - `parseLocalePreference(value)` — anything unrecognised means *auto*, the
     same shape `parseThemeMode` already uses for the theme.
   - `translate(messages, key, params)` — dotted key lookup, `{name}`
     interpolation, missing key returns the key itself so a hole is visible in
     development rather than silent.

3. **`src/services/I18nService.ts` (NEW)**
   - Mirrors `ThemeService`, which is the pattern this app already uses for a
     browser-owned preference: `localePreferenceSignal`, `localeSignal`,
     `setLocalePreference(preference)`, `initLocale()` returning its own cleanup.
   - Remembers the choice in `localStorage` under `rom-manager.locale`, storage
     failures ignored exactly as the theme ignores them.
   - Writes the resolved locale to `document.documentElement.lang`, and while the
     preference is *auto* follows `languagechange` so a browser switched mid
     session switches the app with it.
   - Exports `t(key, params)`, which reads `localeSignal` — so any component that
     calls it re-renders on a locale change without a provider or a context.

4. **`src/app.tsx`** — `useEffect(() => initLocale(), [])` beside `initTheme`.

5. **`src/components/PreferencesModal.tsx`** — a third group, *Idioma /
   Language*: `Automático`, `Español`, `English`, as the same segmented control
   the theme uses, with the hint saying that automatic follows the browser. This
   preference is the browser's, not the library's, so it is never disabled.

## Walkthrough (2026-08-01 03:50)

### Internationalisation

- **`src/core/i18n.ts` (new)** — `LOCALES` (`en`, `es`), `LocalePreference`
  including *auto*, `negotiateLocale` (primary subtag, so `es-419` is Spanish),
  `parseLocalePreference`, `resolveLocale`, `translate` (dotted keys, `{named}`
  interpolation, English fallback, key-on-miss) and `messageKeys`.
- **`src/core/i18n.test.ts` (new)** — 15 tests: negotiation, parsing, resolution,
  interpolation and fallback, plus three over the catalogues themselves — Spanish
  holds every English key, holds no key English lacks, and every sentence keeps
  the same placeholders in both languages.
- **`src/services/I18nService.ts` (new)** — `ThemeService`'s shape:
  `localePreferenceSignal`, `localeSignal`, `setLocalePreference`, `initLocale()`
  returning its cleanup. Remembers the choice under `rom-manager.locale`, writes
  `document.documentElement.lang`, follows `languagechange` while *auto*, and
  exports `t()` reading a computed catalogue — no provider, no context.
- **`src/messages/en.yaml`, `src/messages/es.yaml` (new)** — ~200 keys covering
  the whole interface. English is the reference; the head of the Spanish file
  records the fixed THESAURUS.md equivalences (System→Sistema, Game→Juego,
  Variant→Variante, Consolidate→Consolidar, Cover Art→Carátula…) so a future
  translator does not re-invent them.
- **`vite.config.ts`** — `@rollup/plugin-yaml` (new devDependency), which also
  covers vitest; **`src/types/yaml.d.ts`** types `*.yaml` as a `Messages` record.
  The `tsup` library build only bundles `services/index.ts` and is untouched.
- **`src/app.tsx`** — `initLocale()` beside `initTheme()`.
- **`src/components/PreferencesModal.tsx`** — a *Language* group,
  `Automático / English / Español`, each language named in itself.

### The strings that were already there

Moved into the catalogues and read through `t()`: `ROMExplorer`, `FileTree`,
`RomDetails`, `MetadataEditor`, `MediaDropModal`, `RomIntakeModal`,
`OrganizePanel`, `SystemDetails`, `Tabs`, `PreferencesModal` and `app.tsx` —
about 130 strings, in both directions (English ones like `No folders opened` and
Spanish ones like `Identificando…`). `THEME_MODE_LABELS`, `MEDIA_KIND_LABELS` and
`MEDIA_SCOPE_LABELS` are gone from `core/`: a core module has no business holding
one language's words, so the keys are translated where they are rendered.

The action the panel performs is called **Consolidate / Consolidar** throughout,
which is THESAURUS.md's term for it; it used to say «Organizar» in Spanish and
«rename and sort» in English.

They are catalogue prose rather than interface chrome, and moving them would
double the size of both YAML files; worth a session of its own.
