# Session: Select Added Game After Intake / Drop

Date: 2026-08-01 01:35

## Objective
Automatically select the newly added game / ROM files in the UI and details pane after an intake or drop operation completes.

## Context & Root Cause
In `src/views/ROMExplorer.tsx`:
- `handleIntakeConfirm` and `handleDropConfirm` apply the file copy operations, clear grouping caches, and bump `refreshToken`.
- However, neither function updates `selection` or calls `handleSelectionChange`.
- As a result, after adding a game, the view remains on its previous selection (or no selection), requiring the user to search for and select the newly added game manually.

## Proposed Changes

1. **`src/views/ROMExplorer.tsx`**:
   - In `handleIntakeConfirm`, collect the target paths of placed items (`intake.filter(isPlaced)`). Upon completion, call `setGameFile(undefined)` and `void handleSelectionChange(addedPaths)`.
   - In `handleDropConfirm`, collect target paths of intake items (`taken.filter(isPlaced)`) or copied files (`files`). Upon completion, call `setGameFile(undefined)` and `void handleSelectionChange(addedPaths)`.

2. **Verification**:
   - Run unit tests (`npx vitest run`) to verify all tests pass cleanly.
   - Confirm selection state updates when adding games/ROMs.

## Walkthrough

- **`src/views/ROMExplorer.tsx`**:
  - Updated `handleIntakeConfirm` and `handleDropConfirm` to extract the destination paths of placed/copied files.
  - Added logic invoking `setGameFile(undefined)` and `handleSelectionChange(addedPaths)` right after intake/drop confirmation, automatically selecting the added game/ROM files in the tree and details pane.
