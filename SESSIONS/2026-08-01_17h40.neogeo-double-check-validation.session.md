# 2026-08-01 17h40 — NeoGeo Double-Check Validation & Variant Naming Fixes

Goal: Implement a dual-level verification (structural integrity check + DAT/CRC32 checksum lookup) for NeoGeo variants (both `.neo` and `.zip` format), fix the fallback label when a variant key is `Unknown` (e.g. for arcade/NeoGeo sets like `mslug (1).zip`), and ensure seamless consolidation of duplicate-suffixed filenames to canonical names.

## Context & NeoGeo Variants

NeoGeo games have two levels of variants:
1. **Content variants**: Region (AES JP / AES US / MVS), cartridge revision (`NGM-2530`, `NGH-2510`), prototype, bootleg, or hacks.
2. **File format variants**: 
   - `.neo` (Darksoft/MiSTer single-file format with 512-byte header).
   - `.zip` (MAME/FBNeo split ROMset containing individual P1, C1, S1, M1, V1 chip dumps).

## Proposed Double-Check Engine

For each variant file discovered under `NEOGEO`:

### Check 1: Structural & Format Integrity
- **For `.neo` files**:
  - Read first 512 bytes (header).
  - Verify header magic / flags.
  - Calculate `expectedSize = 512 + P_size + C_size + S_size + M_size + V_size`.
  - Confirm file size matches `expectedSize` exactly.
- **For `.zip` files**:
  - Read ZIP header / Central Directory.
  - Verify all member entries are readable and not corrupted.

### Check 2: DAT / Hash Matching (Checksum Lookup)
- **For `.neo` files**:
  - Match file CRC32 / SHA1 against DAT entries.
- **For `.zip` files**:
  - Read member CRC32 list.
  - Execute `ROMDatasetService.lookupSetByMemberCrcs('NEOGEO', memberCrcs)` to match against dataset set members.

## Fix Variant "Unknown" Labeling & File Consolidation

- When a variant has no region tag (e.g. arcade/MVS sets like `mslug`), fallback `variantKey` from `'Unknown'` to a clean, descriptive label based on DAT extras or set description (e.g. `World / Arcade`, `Standard Set`).
- Ensure filenames with duplicate suffixes like `mslug (1).zip` consolidate cleanly to canonical names (`mslug.zip` or `mslug.neo`).
