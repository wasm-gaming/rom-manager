# Persist FSA Folder Handles Across Refresh

**Date:** 2026-08-01 01:05
**Topic:** Persist opened FSA directory handles in IndexedDB so they survive page refresh

## Context

When the user refreshes the browser tab, all opened FSA folders are lost because the `FileSystemDirectoryHandle` objects live only in memory. The File System Access API supports persisting handles via IndexedDB (structured clone), and the `@cloudauthn/vfs-sync` library already provides `FSAAdapter.fromHandle()` and `ensurePermission()` for restoring them.

## Goal

After a page refresh, the tabs the user had open should reappear. Clicking a tab re-requests permission (browser requirement) and reconnects the folder.

## Constraints

- `FileSystemDirectoryHandle` is **not** JSON-serializable → must use IndexedDB (structured clone)
- Permission is revoked on reload → `ensurePermission()` must be called from a user gesture (click)
- Scope: persist only for the life of the tab session (clear handles on tab close), or persist across sessions — **user preference to decide**
