# Session: Prevent Variants Title Layout Shift

Date: 2026-08-01 02:16

## Objective
Prevent `.variants-title` from shifting position and jumping back when switching between games in the ROM details view.

## Problem Analysis
When switching between games in `RomExplorer`:
1. `ROMExplorer` resets `gameCover` to `undefined` while loading the new game's cover.
2. In `RomDetails`, `CoverFigure` returned `<div class="rom-info-cover-wrapper">` without a `<figure>` or `<figcaption>` when `cover` was `undefined`. Once the cover resolved, `<figcaption class="rom-info-cover-region">` was added below the image. This sudden addition of `<figcaption>` caused a ~20px vertical layout shift on `.rom-info-hero`, pushing `.variants-title` down.
3. Preact reuses the `<CoverFigure>` component instance when switching games. `naturalRatio` state was retained from the previous game's cover, temporarily applying an old aspect ratio (e.g. 4:3 or 1:1) to the new game until `onLoad` fired, causing rapid height jumps.

## Proposed Changes
1. **`src/components/RomDetails.tsx`**:
   - Update `CoverFigure` to always render `<figure class="rom-info-cover-figure">` with a `<figcaption class="rom-info-cover-region">` (using `\u00A0` when `cover` or region is undefined) so hero height remains stable during loading.
   - Synchronously reset `naturalRatio` when `cover?.url` changes so stale aspect ratios from previous games do not persist during transitions.

2. **`src/styles/index.css`**:
   - Ensure `.rom-info-cover-region` maintains consistent min-height/line-height for empty or `\u00A0` content.

## Verification Plan
1. Test switching between games with covers of different aspect ratios.
2. Verify `.variants-title` does not jump or shift position during cover resolution.
3. Run existing automated tests (`npm test`) to ensure no regressions.

## Extension

Date: 2026-08-01 02:21

### Additional Problem Analysis
Resetting `naturalRatio` to `undefined` whenever `cover?.url` became `undefined` (which `ROMExplorer` triggers synchronously on every game selection change) caused `CoverFigure` to temporarily fall back to `defaultRatio` during the 30-50ms window while `CoverService.resolve` resolved the new cover URL.
When the new image loaded, `onLoad` fired and set `naturalRatio` to the image's actual aspect ratio. This resulted in a double layout jump: the cover wrapper collapsed/expanded to `defaultRatio` when `gameCover` became `undefined`, and then jumped back to `naturalRatio` when `onLoad` completed.

### Implemented Fix
- **`src/components/RomDetails.tsx`**:
  - Changed state reset tracking in `CoverFigure` from `url` to `system`. `naturalRatio` is preserved across transient cover loading states within the same system, maintaining a stable wrapper height during loading and preventing `.variants-title` from shifting position. `naturalRatio` resets only when navigating between different console systems.
