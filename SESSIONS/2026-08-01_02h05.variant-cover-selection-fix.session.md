# Session: Variant Cover Selection Fix

Date: 2026-08-01 02:05

## Objective
Fix cover selection so that when a specific revision/variant (e.g. `Super Mario World (Europe) (Rev 1)`) is present or selected while the base release (`Super Mario World (Europe)`) is not added, the application correctly displays the cover of the present/selected variant.

## Problem Analysis
1. `coversOf` in `src/core/rom-covers.ts` ranks variants for a region using `rankOf(variant)`. Both `Super Mario World (Europe)` and `Super Mario World (Europe) (Rev 1)` receive rank 0. Because `Europe` appears first in the variant list, `coversOf` assigns `covers.byRegion.EU` to `Europe.png` and discards `Europe (Rev 1).png`.
2. When the user has only `Super Mario World (Europe) (Rev 1).sfc` on disk:
   - `coversOf` still assigned `Europe.png` for region `EU` because it did not take present variants into account.
   - `pickCover` returned `Europe.png`, which is for the missing release (or returns 404), failing to show the cover of `Super Mario World (Europe) (Rev 1)`.
3. When a specific file/variant is selected (`gameFile`), `pickCover` did not prefer the selected variant's own cover URL.

## Proposed Changes
1. **`src/core/rom-covers.ts`**:
   - Update `coversOf` to accept optional `presentVariantKeys?: Set<string>`.
   - Adjust ranking in `coversOf` so present variants take precedence over missing variants for a region.
   - Add `variantUrl?: string` option to `pickCover` to prefer a specific selected variant's cover.
2. **`src/core/wizard-tree.ts`**:
   - Add `cover?: string` to `WizardVariant`.
   - Pass present variant keys to `coversOf` during tree building.
3. **`src/views/ROMExplorer.tsx`**:
   - Pass the selected file's variant cover URL into `pickCover`.
4. **`src/components/RomDetails.tsx`**:
   - Ensure `isCoverActive` in `VariantRow` prioritizes exact `cover.url` matching.
5. **`src/core/rom-covers.test.ts`**:
   - Add unit tests for `coversOf` with present variants and `pickCover` with `variantUrl`.
