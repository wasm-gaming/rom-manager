# Preserve Game Selection when Consolidating Variant Name

Date: 2026-08-01 05:13

## Objective
Ensure that when a variant file's name is consolidated (or organized), the currently selected game remains selected in the details pane and file tree, updating its file paths and consolidation status without deselecting the game.

## Context & Root Cause
Currently, when a user clicks the consolidate button on a variant file in `RomDetails` (or consolidates files via `OrganizePanel`), `handleOrganizeConfirm` calls `invalidateTree()` in `src/views/ROMExplorer.tsx`.

`invalidateTree()` was explicitly clearing selection and state:
```tsx
  const invalidateTree = useCallback(() => {
    grouping.current.clear();
    setGroupedRows(new Map());
    storeService.setSelection([]);
    setRecords(new Map());
    setStats(new Map());
    setGame(undefined);
    setGameFile(undefined);
    setTreeVersion((version) => version + 1);
  }, []);
```
Because `setGame(undefined)`, `storeService.setSelection([])`, and `setTreeVersion((version) => version + 1)` (which unmounts and remounts `FileTree`) were executed, any active game selection was completely cleared.

`FileTree` already possesses an automatic `useEffect` hook (lines 383-388 of `FileTree.tsx`) that re-selects `selectedGame` when `rows` update:
```tsx
  useEffect(() => {
    if (!selectedGame) return;

    const row = rows.find((candidate) => candidate.key === selectedGame);
    if (row?.game && row.game !== reportedGame.current) selectPaths(new Set(row.paths), row.game);
  }, [rows, selectedGame, selectPaths]);
```

By preserving `FileTree`'s mounted state and preserving `game` / `selectedGame` during `invalidateTree()`, `FileTree` will automatically match the preserved `selectedGame` key against the newly grouped rows, updating the selection and `game` object with the newly consolidated file paths.

## Proposed Changes

1. **`src/views/ROMExplorer.tsx`**:
   - Update `invalidateTree()`:
     - Remove `setGame(undefined)`, `setGameFile(undefined)`, `storeService.setSelection([])`, and `setTreeVersion((version) => version + 1)`.
     - Call `grouping.current.clear()`, `setGroupedRows(new Map())`, `setRecords(new Map())`, `setStats(new Map())`, and `setRefreshToken((t) => t + 1)`.
   - When `groupedRows` is re-generated via `handleGroupingNeeded`, `FileTree` will re-match `selectedGame` and fire `onGameChange` / `onSelectionChange` with the updated `WizardGame` node.
