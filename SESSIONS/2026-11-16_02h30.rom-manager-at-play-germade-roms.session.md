## Why the owner does not see the phone panels at play.germade.dev/roms/

play.germade's `/roms/` is still **its own manager** (`src/roms/`, ~1 100 lines in rom-manager's
look) over **its own library** (`library/<system>/`). rom-manager 0.2.x, with the panels, is only
on GitHub Pages. The swap was agreed (base `/roms/`, one library) but not built.

## What swapping means: play.germade's manager does things rom-manager does not (yet)

| play.germade's `/roms/` today | rom-manager |
| --- | --- |
| **Mods**: IPS / BPS / UPS imported one by one, auto-assigned by source CRC, renamed, assigned / unassigned, "Jugar con el mod" | none (it was "step 3" of the last session) |
| **Engine per system and per game** ("Motor por defecto") | none (a launcher concern) |
| **"Jugar"** → `/<system>/?game=…&version=…` | none |
| Neo Geo sets against fbneo's dataset, the BIOS (`neogeo.zip`) | NEOGEO romset validation by member checksums (its own DATs) |
| content-addressed files + `index.json` (games → versions with sha1, mods, core) | `<System>/<file>` + `.meta/` (per-game JSON, covers, `scan.json` hash cache) |

Swapping before these exist would take features away from players. So the swap comes in steps, each
releasable.

## Plan

### A. Mods in rom-manager (the old "step 3")

- **Storage**: `.meta/<System>/mods/<sha1>.<ips|bps|ups>`, outside the ROM folders so that scans
  and organizing never see them. Each game's `.meta/<System>/<Game>.json` gets
  `mods: [{ sha1, name, format, sourceCrc, targetCrc?, assignedTo? }]`.
- **Intake**: patches join the existing "Añadir ROMs" intake. BPS / UPS find their game by source
  CRC; IPS by choice (the game that is open, or "sin asignar"). Mods can be renamed, reassigned
  and removed.
- **Details** (desktop) and **panel 4** (phone): the game's mods, with their status (fits a version
  / does not), and "Jugar con este mod" when hosted by play.germade (C).
- The patch parser / applier is small. play.germade's `patch.js` (206 lines) is ported to TS, with
  tests (IPS / BPS / UPS, CRC checks).

### B. The library index for other apps — `.meta/<System>/index.json`

play.germade needs, per system, games → versions (file path, sha1, crc) and their mods, and must not
re-hash or re-group what rom-manager already knows. rom-manager writes **one versioned index per
system** after every change (intake, delete, organize, rename, mods):
`{ "version": 1, "games": { "<gameId>": { "title", "versions": [{ "path", "sha1", "crc", "region", "revision", "verified" }], "mods": [...] } } }`.

**`gameId` = the slug play.germade uses today** (the DAT base title), so the saves that engines keep
in `<engine>/<gameId>/` stay where they are. It is a documented contract in STACK.md, with a test
that pins the shape.

### C. Hosted at play.germade's `/roms/`

- **Build**: `npm run build -- --base /roms/` → `dist-roms/`. The release attaches
  `rom-manager-roms.tar.gz` (the Pages build at `/rom-manager/` stays as it is).
- **Host mode** (only when served under play.germade: a build flag, `VITE_HOST=play.germade`):
  - "Jugar" on a version, and "Jugar con este mod", link to `/<route>/?game=<gameId>&version=<sha1:8>&patch=<sha1:8>`.
    The route comes from a system → launcher-route map (`MegaDrive` → `megadrive`, `SNES` → `snes`,
    `GBA` / `GAMEBOY` / `GAMEBOY COLOR` → the launcher's GBA / GB / GBC routes, `NEOGEO` → `neogeo`).
  - A "← Lanzador" link in the header.
- **One-time migration** of play.germade's library on first open in host mode. If OPFS
  `library/<system>/index.json` exists:
  - its ROMs go through the normal intake, so they are named and placed by the DATs;
  - its patches become mods, assigned to the same games;
  - its game titles renamed by the player are kept in the game's `.meta`;
  - a marker (`.meta/migrated-from-play-germade.json`) is written.

  The old folder is **not** deleted here: play.germade removes it once it reads the new index.
- **COOP / COEP**: already checked (2026-11-15 22:08 note): covers keep working isolated.

### D. Styles: 768 / 460 / fluid below 460 (the owner, 2026-11-16)

"We keep the style switch at 768px, adjust it so it looks right at 460px, and below 460px we use vw
for the root font-size, which lets us use rem for every measure and scale linearly."

- The phone switch (`PHONE_QUERY` in `ROMExplorer.tsx` and the CSS `@media`) moves from 760px to
  **768px**. The 640px rules are folded into it or into 460px.
- **≤ 460px**: `:root { font-size: calc(100vw / 28.75); }` (16px at 460px), so the whole UI scales
  with the screen.
- **Every measure becomes `rem`**: the 172 `px` values in `src/styles/index.css` and the 2 in TSX,
  except 1px hairlines (borders, dividers).
- Checked at 768, 460, 390 and 320 wide, portrait and landscape.

### E. Languages

rom-manager is already in es / en. The new rule ("all the UI in English and Spanish, falling back to
English; all code in English") holds: every new string goes into both tables.

## Order and releases

1. **D** (styles) — small, visible, releasable on its own: rom-manager 0.3.0.
2. **A + B** (mods, index): 0.4.0.
3. **C** (`/roms/` build, host mode, migration): 0.5.0.
4. play.germade switches (its record): pins the rom-manager release and copies it to `dist/roms/`,
   reads `.meta/<System>/index.json`, removes `src/roms/` and its old library after the migration,
   keeps the engine choice in its own `library-prefs.json` and shows it in the system page's drawer,
   and adds a cache-first SW route for `/roms/` assets.

Verification at each step: `vitest`, `tsc`, `vite build`; Chromium as an iPhone 13 and as a Pixel 7,
both orientations. For C and the switch: a play.germade library with ROMs and mods migrated, a game
played from `/roms/`, saves where they were.
