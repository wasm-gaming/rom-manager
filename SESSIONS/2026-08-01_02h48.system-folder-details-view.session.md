## 2026-08-01 - Console Info Only for Wizard Folders (proposal)

### The problem

`RomDetails` renders `<SystemDetails folder={folder} />` for any selected folder,
and `SystemDetails` resolves the system from the **first path segment** of the
folder (`getSystemInfo`). So a folder that is *not* browsed grouped by game —
either a plain subfolder such as `nes/collections`, or a system folder the user
explicitly switched out of wizard mode — still shows the console hero, its
description and its habitual extensions. Console info is the wizard's promise;
a plain listing has no business claiming a system.

### Planned Changes

1. **`src/components/SystemDetails.tsx`**
   - Accept `wizard: boolean`.
   - Resolve the system only when the folder is browsed grouped
     (`const info = wizard ? getSystemInfo(folder) : undefined`), so a non-wizard
     folder always falls into the existing generic folder card (generic logo,
     folder name, path) and never renders the console hero, description or
     extension pills.

2. **`src/components/RomDetails.tsx`**
   - Add `wizardFolder?: boolean` to `RomDetailsProps` and pass it through to
     `<SystemDetails wizard={...} />`.

3. **`src/views/ROMExplorer.tsx`**
   - Pass `wizardFolder={folder !== undefined && isGrouped(folder)}`, which is the
     same `isWizardFolder(path, wizardSettings, knownSystems)` decision the tree
     itself groups by — one source of truth, no second heuristic.

### Verification Plan

- `npm run type-check`, `npm run test`, `npm run lint`.
- Manual: select a system folder (console info shown), toggle grouping off (card
  becomes the generic folder card), select a subfolder of a system (generic card).

### Walkthrough (approved: generic card for non-wizard folders)

- **`src/components/SystemDetails.tsx`** — new required `wizard: boolean` prop.
  `getSystemInfo` is only consulted when it is true, so a folder browsed as a
  plain listing falls into the generic card and never renders the console hero,
  the description or the extension pills. The generic card's heading now shows
  the folder's own name instead of its whole path (the path stays in the facts
  row) — that branch used to only ever see root-level names, and now it sees
  nested ones.
- **`src/components/RomDetails.tsx`** — `wizardFolder?: boolean` in
  `RomDetailsProps`, defaulting to `false`, passed straight through.
- **`src/views/ROMExplorer.tsx`** — `wizardFolder={folder !== undefined && isGrouped(folder)}`,
  the same `isWizardFolder(path, wizardSettings, knownSystems)` the tree groups by.

### Verification

- `npm run type-check`: clean.
- `npx vitest run`: 347 passing (21 files). Note `npm run test` is `vitest` in
  watch mode and does not exit on its own.
- `npm run lint`: no new warnings; the reported ones are all pre-existing.
- Not verified visually: no browser automation available here.
